# Соседи — neighborhood-frontend

Соседи — приложение для поиска и предложения услуг внутри жилых комплексов.
Жители могут найти исполнителя рядом с домом, посмотреть его профиль и связаться
с ним в Telegram или WhatsApp. Исполнители публикуют услуги и выбирают адреса домов,
в которых готовы помогать соседям.

Этот репозиторий содержит адаптивный веб-клиент backend-проекта
[neighborhood](https://github.com/DanilFlint/neighborhood). Интерфейс на русском,
синяя палитра, готовые компоненты Ant Design, плавные переходы с учётом
`prefers-reduced-motion`.

Репозиторий фронтенда: [neighborhood-frontend](https://github.com/DanilFlint/neighborhood-frontend).

## Требования и установка

- **Node.js 24 LTS**.
- **pnpm 11.25.0** (`npm install -g pnpm@11.25.0`, если pnpm ещё не установлен).
- Backend neighborhood на порту 8080 с настроенными PostgreSQL и JWT-секретами.

Из PowerShell:

```powershell
git clone https://github.com/DanilFlint/neighborhood-frontend.git
cd neighborhood-frontend
pnpm install --frozen-lockfile
Copy-Item .env.example .env.local
pnpm dev
```

Откройте [http://localhost:5173](http://localhost:5173).
Для обычного повторного запуска достаточно `pnpm dev`.
Lockfile фиксирует версии зависимостей и хранится в репозитории.

В отдельном терминале запустите backend:

```powershell
cd ..\neighborhood\heighborhood-app
. .\scripts\load-local-env.ps1
.\gradlew.bat --no-daemon run
```

Подробности подключения БД — в `../neighborhood/docs/authentication.md`.
Предварительное заполнение ЖК не требуется. Адреса России ищутся в открытой
базе OpenStreetMap через backend и Photon; выбрать дом также можно на карте
Leaflet/OSM. Вводите город, улицу и номер дома, затем подтвердите подсказку.
Произвольный текст и точка без найденного адреса не сохраняются.
Нужна миграция backend V6. Публичный Photon не требует API-ключа, но ограничивает
нагрузку и не гарантирует полноту адресов. Backend-провайдер настраивается через
`NEIGHBORHOOD_ADDRESSES_PHOTON_URL`, тайлы — через `VITE_OSM_TILE_URL`.
Контракты и сохранение старых данных: `../neighborhood/docs/address-selection.md`.

`API_PROXY_TARGET` в `.env.local` задаёт адрес backend, например
`http://localhost:8080`. После его изменения перезапустите Vite.
Браузер обращается к `/api/v1`; dev-сервер проксирует запросы, поэтому CORS
на backend для локальной разработки менять не требуется.

Для проверки с телефона используйте Network URL, который выводит Vite,
например `http://192.168.0.10:5173`, находясь в той же сети. Разрешите входящие
подключения к порту 5173 в брандмауэре при необходимости. `localhost` на телефоне
указывает на сам телефон. Backend может оставаться на localhost компьютера:
запросы проходят через Vite.

## Страницы и готовые сценарии

| Путь | Возможности |
| --- | --- |
| `/` | Публичный каталог, категории, поиск адреса и карта, пагинация; фильтры в URL |
| `/services/:id` | Фото, описание, цена, покрытие, контакты исполнителя |
| `/users/:id` | Публичный профиль, адреса, мессенджеры и услуги с пагинацией |
| `/register` | Регистрация с обязательным основным адресом; затем отдельный вход |
| `/login` | Вход по email и паролю, возврат на запрошенную страницу |
| `/me` | Просмотр email, редактирование имени, HTTPS-фото, описания и контактов |
| `/me/locations` | Основной и дополнительные адреса из поиска или карты |
| `/my-services` | Собственные опубликованные услуги и переход к редактированию |
| `/services/new` | Публикация с категорией, ценой, фото и независимым покрытием |
| `/services/:id/edit` | Полная замена собственной услуги |
| `/health` | Проверка доступности HTTP backend, без проверки БД |

Авторизованные страницы защищены; при истечении сессии предлагается вход.
Реализованы загрузка, пустые состояния, повтор запроса и понятные ошибки.
Изменения профиля, локаций и услуг обновляют кэш RTK Query.
Контакты публичны; переходы в Telegram/WhatsApp выполняются по проверенным ссылкам.
Валюта не задана backend, поэтому фронтенд её не придумывает.
Удаление, черновики, рейтинги, восстановление пароля и загрузка файлов
не представлены: backend пока не поддерживает их.

## Стек и структура

React **19.3.1**, Redux Toolkit **2.14.0**, React Redux **9.3.1**,
Ant Design **6.6.8**, React Router **7.18.5**, TypeScript, Vite.
У React [нет отдельного LTS-канала](https://react.dev/community/versioning-policy):
использован стабильный Latest, без Canary/Experimental. Для Redux выбран
[официально рекомендуемый Redux Toolkit](https://redux.js.org/introduction/getting-started).
Node.js использует LTS-линию 24. Точные версии всех зависимостей — в `package.json` и `pnpm-lock.yaml`.

- `src/api` — типы DTO, RTK Query endpoints, обновление access-токена.
- `src/app` — store, сессия, маршруты, тема и навигация.
- `src/pages` — бизнес-страницы и формы.
- `src/components` — предметные композиции готовых компонентов Ant Design.
- `src/lib` — валидация и форматирование.
- `e2e` — браузерные проверки с контролируемыми HTTP-ответами.

Правило **не писать собственные базовые UI-компоненты** закреплено в `AGENTS.md`.

## Сессия

Access/refresh-токены хранятся только в памяти Redux. После обновления вкладки
нужно войти заново. Redux DevTools отключены, токены не записываются в storage
или логи. При 401 выполняется один общий refresh для конкурентных запросов
с ротацией токенов по контракту Micronaut. При отказе refresh сессия очищается.
Выход отзывает refresh на сервере и очищает локальный кэш. Если сервер недоступен,
локальный выход всё равно выполняется, интерфейс сообщает, что отзыв не подтверждён.

## Проверки и сборка

```powershell
pnpm test
pnpm build
pnpm exec playwright install chromium
pnpm test:e2e
```

Браузерные проверки используют отдельный dev-сервер на 5173 и перехватывают API:
они проверяют клиентские сценарии и контракты запросов, но не заменяют сквозную
проверку с настоящим PostgreSQL/backend. Закройте другой dev-сервер на 5173
перед их запуском. Для проверки установленного Edge можно задать
`$env:PLAYWRIGHT_CHANNEL = 'msedge'` перед `pnpm test:e2e`.

Чтобы прогнать те же сценарии на собранном `dist/`, после `pnpm build` задайте
`$env:E2E_PREVIEW = '1'` и запустите `pnpm test:e2e`. После проверки удалите
переменную командой `Remove-Item Env:E2E_PREVIEW` для возврата к dev-серверу.

`pnpm build` проверяет TypeScript и собирает `dist/`.
`pnpm preview` позволяет посмотреть production-сборку на порту 4173, но **не
проксирует API**. Для полноценных сценариев используйте `pnpm dev` или production
reverse proxy с `/api` → backend и SPA fallback на `index.html` для остальных путей.
Секреты backend не должны попадать в `VITE_*` переменные и браузерный bundle.

Проверено 3 ноября 2026 года: `pnpm test` — 8 тестов, `pnpm build` — успешно,
14 браузерных проверок production-сборки в Edge — успешно (ширина 1440, 393 и
320 px). Проверки используют тестовые HTTP-ответы; реальный backend в этой
проверке не запускался. Vite сообщает рекомендательное предупреждение о размере
общего JS-чанка (~687 kB, ~226 kB gzip); страницы загружаются лениво.

### Адреса и карта

Поиск отправляется после паузы 650 мс, от 3 символов. Сначала выбирается
подсказка, затем её UUID используется в формах регистрации, локаций и услуг.
На карте нужно нажать дом и подтвердить один из адресов не дальше 150 м.
Для клавиатуры доступны стрелки, масштаб и кнопка поиска в центре карты.
При недоступности провайдера отображается ошибка; вымышленные адреса не добавляются.
Старые привязки и выбор конкретных домов остаются до смены адреса.
Имена API-полей `residentialComplexId` сохранены для совместимости; новый UI
не запрашивает справочник ЖК. Новое покрытие относится к выбранному адресу,
поиск по радиусу и автоматическое сопоставление прежних ЖК новым домам не реализованы.

Для отдельного порта браузерных проверок задайте `$env:E2E_PORT = '5184'`.

Проверено 4 ноября 2026: `pnpm test` — 8 тестов, `pnpm build` — успешно;
29 браузерных проверок production-сборки в Edge — успешно, включая карту
и выбор адреса на экранах 1440, 393 и 320 px. Ответы API и тайлы в E2E
контролируемые; реальный Photon отдельно проверен запросом российского адреса.
